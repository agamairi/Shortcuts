## 2. New & Remaining Defects Ranked by Severity

### CRITICAL

#### [NEW-1] `ShortcutSteps.updateV2Step` leaves stale `VerificationPostcondition` and `ExpectedWindow` after editing `SET_TEXT` or `LaunchAppStep`, causing 100% replay failure
- **Location:** [`ShortcutSteps.kt:329-334, 378-380`](../../app/src/main/java/com/shortcuts/app/data/ShortcutSteps.kt#L329-L380), [`RecordingCompiler.kt:526-528, 569-592`](../../app/src/main/java/com/shortcuts/app/automation/capture/RecordingCompiler.kt#L526-L592), [`ReplayStateMachine.kt:170-177, 743`](../../app/src/main/java/com/shortcuts/app/automation/replay/ReplayStateMachine.kt#L170-L177)
- **Failure Scenario:**
  1. **Edited `SET_TEXT`:** During recording, [`RecordingCompiler.verificationFor`](../../app/src/main/java/com/shortcuts/app/automation/capture/RecordingCompiler.kt#L526-L528) attaches `VerificationPostcondition.TextEquals(spec.text)` (e.g., `"Alice"`) to `UiStep.verification`. When the user edits the typed text in `ManualBuilderScreen` or `RecorderScreen` to `"Bob"`, [`ShortcutSteps.updateV2Step`](../../app/src/main/java/com/shortcuts/app/data/ShortcutSteps.kt#L378-L380) updates `step.action` to `ActionSpecification.SetText("Bob", ...)` but leaves `step.verification` with `TextEquals("Alice")`. On replay, the engine types `"Bob"` into the field, then [`ReplayStateMachine.verify`](../../app/src/main/java/com/shortcuts/app/automation/replay/ReplayStateMachine.kt#L743) asserts the field equals `"Alice"` and fails the run with `VERIFICATION_FAILED`.
  2. **Edited `LaunchAppStep`:** When the user changes a recorded `LaunchAppStep` from package `A` to package `B`, [`ShortcutSteps.updateV2Step`](../../app/src/main/java/com/shortcuts/app/data/ShortcutSteps.kt#L330-L333) writes `expectedWindow = step.expectedWindow.copy(packageName = newPkg)` while keeping package `A`'s `observedActivityClass`, `titleToken`, `fingerprint`, and `expectedAfter`. On replay, [`waitForExpectedWindow`](../../app/src/main/java/com/shortcuts/app/automation/replay/ReplayStateMachine.kt#L170-L177) requires package `B`'s window to match package `A`'s activity class and title token, failing 100% of the time with `EXPECTED_SCREEN_TIMEOUT`.
  3. **App-shortcut picker loss:** In [`ManualBuilderScreen.kt:792-801`](../../app/src/main/java/com/shortcuts/app/ui/screens/ManualBuilderScreen.kt#L792-L801), picking a deep-link/shortcut on a `v2StepId` step preserves `v2StepId`, and [`ShortcutSteps.updateV2Step`](../../app/src/main/java/com/shortcuts/app/data/ShortcutSteps.kt#L330-L333) wraps only `LaunchTarget.Package(newPkg)`, silently discarding `intentAction`, `url`, and `target` (`componentName`).
- **Minimal Fix:**
  - In [`ShortcutSteps.updateV2Step`](../../app/src/main/java/com/shortcuts/app/data/ShortcutSteps.kt#L378-L380), when updating `ActionSpecification.SetText`, also map `step.verification.postconditions` so any `VerificationPostcondition.TextEquals(oldStepAction.text)` is replaced with `VerificationPostcondition.TextEquals(newText)`.
  - In [`ShortcutSteps.updateV2Step`](../../app/src/main/java/com/shortcuts/app/data/ShortcutSteps.kt#L330-L333), when `newPkg != oldPkg` (or when `intentAction`/`url` is added), clear `observedActivityClass = null`, `titleToken = null`, `fingerprint = null`, and `expectedAfter = null` on `expectedWindow`, and map `intentAction`/`url`/`target` to `LaunchTarget.ImplicitIntent` / `LaunchTarget.DeepLink` / `LaunchTarget.ExplicitComponent`.

#### [NEW-2] `validateLiveIdentity` rejects every `scrollToFind` reveal scroll and every composite (descendant-labelled) control in Engine v2
- **Location:** [`ReplayStateMachine.kt:404-410, 836-840`](../../app/src/main/java/com/shortcuts/app/automation/replay/ReplayStateMachine.kt#L404-L410), [`AndroidUiEnvironment.kt:176-183, 336-356`](../../app/src/main/java/com/shortcuts/app/automation/runtime/AndroidUiEnvironment.kt#L336-L356), [`SelectorExtractor.kt:51-55`](../../app/src/main/java/com/shortcuts/app/automation/capture/SelectorExtractor.kt#L51-L55), [`CandidateScorer.kt:76-96`](../../app/src/main/java/com/shortcuts/app/automation/matching/CandidateScorer.kt#L76-L96)
- **Failure Scenario:**
  1. **All `scrollToFind` scrolls rejected:** When a target element is off-screen, [`ReplayStateMachine.scrollToFind`](../../app/src/main/java/com/shortcuts/app/automation/replay/ReplayStateMachine.kt#L404-L410) dispatches a `SCROLL` `UiActionRequest` on `container.nodeId` without passing `targetSelector`. In [`AndroidUiEnvironment.perform`](../../app/src/main/java/com/shortcuts/app/automation/runtime/AndroidUiEnvironment.kt#L178), `val targetSelector = request.targetSelector ?: step.element` substitutes the **off-screen child element's selector**! [`validateLiveIdentity`](../../app/src/main/java/com/shortcuts/app/automation/runtime/AndroidUiEnvironment.kt#L345-L354) then checks whether the `RecyclerView`/`ScrollView` live node has the child button's `TEXT_EXACT`, `CONTENT_DESCRIPTION_EXACT`, or `RESOURCE_ID_EXACT`. It does not, so `validateLiveIdentity` returns `"Live node text changed before dispatch"` and aborts every scroll!
  2. **All composite (descendant-labelled) controls rejected:** Standard Android/Compose rows and buttons are clickable containers (`FrameLayout`/`LinearLayout`/`View` with `text = null`) whose visible text lives on a child `TextView`. [`SelectorExtractor.extract`](../../app/src/main/java/com/shortcuts/app/automation/capture/SelectorExtractor.kt#L51-L55) extracts `TEXT_EXACT` from `findBestDescendantLabel`, and [`CandidateScorer`](../../app/src/main/java/com/shortcuts/app/automation/matching/CandidateScorer.kt#L76-L96) matches the clickable container via descendant text. However, [`AndroidUiEnvironment.validateLiveIdentity`](../../app/src/main/java/com/shortcuts/app/automation/runtime/AndroidUiEnvironment.kt#L345-L354) checks `liveNode.text?.toString() != strategy.value` directly on the unlabelled clickable container `liveNode` (and uses raw `!=` instead of `TextNormalizer.sameText`), returning `"Live node text changed before dispatch"` on every tap on a composite row/button!
- **Minimal Fix:**
  - In [`ReplayStateMachine.scrollToFind`](../../app/src/main/java/com/shortcuts/app/automation/replay/ReplayStateMachine.kt#L404-L410), pass `targetSelector = step.element?.scrollContainer`, and in [`AndroidUiEnvironment.perform`](../../app/src/main/java/com/shortcuts/app/automation/runtime/AndroidUiEnvironment.kt#L178), do not fall back to `step.element` when `request.action is ActionSpecification.Scroll`.
  - In [`AndroidUiEnvironment.validateLiveIdentity`](../../app/src/main/java/com/shortcuts/app/automation/runtime/AndroidUiEnvironment.kt#L345-L354), compare against the snapshot's `targetNode` properties (or walk `liveNode` + its shallow descendants using `TextNormalizer.sameText`) rather than requiring the container `AccessibilityNodeInfo` itself to carry the descendant's `text`/`contentDescription`/`viewIdResourceName`.

#### [NEW-3] Upgrading from v0.7.4 destroys all existing home-screen widgets because legacy `<receiver>` declarations were removed from `AndroidManifest.xml`
- **Location:** [`AndroidManifest.xml:94-110`](../../app/src/main/AndroidManifest.xml#L94-L110), [`AppDatabase.kt:119-167`](../../app/src/main/java/com/shortcuts/app/data/AppDatabase.kt#L119-L167), [`UnifiedShortcutWidget.kt:150-154`](../../app/src/main/java/com/shortcuts/app/widget/UnifiedShortcutWidget.kt#L150-L154)
- **Failure Scenario:**
  - In [`AndroidManifest.xml:94-110`](../../app/src/main/AndroidManifest.xml#L94-L110), the `<receiver>` entries for `.widget.AutomationWidgetReceiver`, `.widget.ListWidgetReceiver`, `.widget.CustomWidgetReceiver`, `.widget.GridWidgetReceiver`, and `.widget.GreetingWidgetReceiver` were deleted, and their receiver classes were removed from `com.shortcuts.app.widget`.
  - Android's `AppWidgetServiceImpl` binds every placed `appWidgetId` to the exact `ComponentName` of its `<receiver>`. When a v0.7.4 user updates the app from Google Play, Android sees that those provider components no longer exist in `AndroidManifest.xml` and **immediately purges every existing widget from the user's home screen**, rendering [`AppDatabase.MIGRATION_6_7`](../../app/src/main/java/com/shortcuts/app/data/AppDatabase.kt#L119-L167) ineffective.
